# Writing News

Every entry is one file in `news/`. The file name is its id, so `news/update-1.yml` is opened with
`/aquabook open update-1`.

The fastest way to start is writing the book in game and running `/aquabook create <id>` with it in
your hand. `/aquabook create template` writes a commented file with every option instead.

## Options

```yaml filename="news/hi.yml"
title: "<color:#33CCFF>Hi</color>"
author: "Aquatic Studios"
date: "01/01/26"
timestamp: 0

icon: ENCHANTED_BOOK
custom-model-data: 0
permission: ""
auto-open: true
footer: true
lore: []
```

| Key | What it does |
| --- | --- |
| `title` | Book title, also the name in the history menu |
| `author` | Shown as the book author |
| `date` | Shown in the menu, written with `date-format` from `config.yml` |
| `timestamp` | Used to sort, newest first. `0` falls back to `date` |
| `icon` | Icon in the history menu |
| `custom-model-data` | Model data for resource packs |
| `permission` | Node needed to see the entry. Empty means everyone |
| `auto-open` | `false` keeps it in the history but never opens it on join |
| `footer` | `false` hides the like, read and history line |
| `lore` | Custom icon lore. Empty uses the one from `messages.yml` |

<Callout type="info">
  The newest entry is the one that opens on join. `/aquabook create` stamps the current time, so a
  new entry always goes first.
</Callout>

## Pages

`pages` is a list of pages, and every page is a list of text chunks. A chunk is either plain text or
a map with one action.

```yaml filename="news/update.yml"
pages:
  # page 1
  - - "&0&lPlain text

"
    - "&4Red &2green &1blue

"
    - text: "&2Go to page 2 &a>"
      hover: "&dJumps ahead"
      page: 2

  # page 2
  - - "&0&lLinks

"
    - text: "&2Open a website &a>"
      url: "https://www.spigotmc.org/"
```

| Action | What it does |
| --- | --- |
| `hover` | Text shown when the cursor is over the chunk |
| `url` | Opens a link, the client asks first |
| `command` | Runs a command as the player |
| `suggest` | Writes the text in the chat box |
| `copy` | Copies the text to the clipboard |
| `page` | Jumps to another page of the same book |

`hover` can go together with any of the others.

<Callout type="warning">
  A page fits about 19 characters per line and 14 lines, and the footer takes 3 of them on the page
  it sits on. Use `
` for a line break and `

` for a blank line.
</Callout>

## Placeholders

| Placeholder | Returns |
| --- | --- |
| `%title%` | Title of the entry |
| `%author%` | Its author |
| `%date%` | Its date |
| `%id%` | Its id |
| `%likes%` | Likes, including the ones set with `setlikes` |
| `%views%` | Times it was opened |
| `%player%` | The reader |
| `%version%` | AquaBook version |
| `%server-version%` | Minecraft version of the server |

Any PlaceholderAPI placeholder works too, like `%player_name%`.

## Colours

| Format | Example |
| --- | --- |
| Legacy | `&a`, `&l` |
| Hex | `&#RRGGBB` |
| MiniMessage | `<bold>`, `<#RRGGBB>`, `<gradient:#33CCFF:#0F6E9E>`, `<rainbow>` |

The page is light, so keep the text dark. Plain text without a colour uses `book.default-color` from
`config.yml`.

## Footer

The line at the bottom of the book: likes, a read mark and a shortcut to the history.

```
❤ 172   ·   ✔ Ok   ·   ≡≡≡
```

Where it goes and what each button does is set in [Configuration](./configuration#book), the text
in `messages.yml`:

```yaml filename="messages.yml"
book:
  footer-prefix: "


"
  footer-separator: "&8   ·   "

  like: "&c❤ %likes%"
  like-hover: "&dClick to leave your like &c❤"
  liked: "&7❤ %likes%"
  liked-hover: "&7Thanks for your like &c❤"

  read: "&9✔ Ok"
  read-hover: "&fClick to mark it as read &9✔"
  already-read: "&7✔"
  already-read-hover: "&7You already marked this one as read"

  menu: "&9&n≡≡≡"
  menu-hover: "&fClick to see more news"
```
