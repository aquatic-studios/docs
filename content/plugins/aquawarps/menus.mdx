# Menus

Every menu is one file in `menus/`. Same shape in all of them, so learning one is learning all 30.
Open any of them with `/aquawarps open <menu> [warp]`.

## Structure

```yaml filename="menus/main.yml"
menu_title: '&8AquaWarps'
size: 45

items:
  browse:
    material: COMPASS
    slot: 10
    display_name: '&#FFEE00&lBrowse Warps'
    lore:
      - '&7Walk through every warp the'
      - '&7community has published.'
      - ''
      - '&#54ADF4Total warps: &f%aquawarps_total%'
    left_click_commands:
      - '[menu] browse'
```

| Key | What it does |
| --- | --- |
| `menu_title` | GUI title |
| `size` | Slots, a multiple of 9 |
| `permission` | Node needed to open the menu |
| `material` | Any material of your version, or a custom item |
| `slot` / `slots` | Position, zero indexed. `slots` places the same item in many |
| `amount` | Stack size |
| `custom-model-data` | Model data for resource packs |
| `glow` | Enchant glint |
| `display_name` / `lore` | Item text, placeholders work |
| `left_click_commands` | Actions on left click |
| `right_click_commands` | Actions on right click |
| `shift_left_click_commands` | Actions on shift + left click. Falls back to left click |
| `shift_right_click_commands` | Actions on shift + right click. Falls back to right click |

<Callout type="info">
  A lore line that renders to `<skip>` is dropped instead of printed. That is how optional lines
  disappear cleanly, like the description of a category that has none.
</Callout>

## Item options

| Option | What it does |
| --- | --- |
| `permission` | Node needed to see it |
| `head` | Renders a player head. A name, `%viewer%` or `%warp_owner%`, needs `PLAYER_HEAD` |
| `requires-warp` | Marks a button that only makes sense with a warp behind the menu |
| `no-warp` | A whole replacement item shown instead when the menu has no warp |

```yaml
  travel:
    material: ENDER_PEARL
    slot: 13
    requires-warp: true
    display_name: '&#FFEE00&lTravel'
    left_click_commands:
      - '[warp] %warp_name%'
    no-warp:
      material: BARRIER
      display_name: '&#FF2D2D&lNo warp selected'
      lore:
        - '&7Open this menu from a warp.'
```

## Custom textures

Any button takes an ItemsAdder, Oraxen or Nexo item as its material, or a vanilla item with
`custom-model-data`.

```yaml filename="menus/main.yml"
  browse:
    material: itemsadder:aquawarps:browse_icon
    slot: 10

  categories:
    material: oraxen:warp_categories
    slot: 11

  favorites:
    material: PAPER
    custom-model-data: 1001
    slot: 12
```

| Material | Plugin |
| --- | --- |
| `itemsadder:namespace:id` or `ia:namespace:id` | ItemsAdder |
| `oraxen:id` | Oraxen |
| `nexo:id` | Nexo |

<Callout type="info">
  If the plugin is not installed or the id does not exist, the button falls back to a vanilla item
  instead of breaking the menu.
</Callout>

## Slots

Every `slots` list takes single numbers and ranges.

```yaml filename="menus/sort.yml"
  slots:
    - 10-16
    - 19-25
```

`[0-44]`, `[0-8, 36-44]` and `0-8, 36-44` work too.

## Filler

Every menu has an optional filler that covers empty slots.

```yaml filename="menus/main.yml"
filler:
  enabled: false
  material: BLACK_STAINED_GLASS_PANE
  display_name: ' '
  custom-model-data: 0
  slots:
    - 0-44
```

| Key | What it does |
| --- | --- |
| `enabled` | Turns it on. Off by default |
| `material` | Any material or custom item |
| `display_name` / `lore` | Item text |
| `custom-model-data` | Model data for resource packs |
| `slots` | Where it goes. Empty fills every free slot |

It never covers a button, and in paged menus it leaves the list slots alone.

## Lists

A menu that shows warps uses `content` instead of fixed items. One entry is rendered per result and
paged across the slots you give it.

```yaml filename="menus/browse.yml"
content:
  source: warps
  slots:
    - 0-44
  item:
    material: GRASS_BLOCK
    display_name: '%promotion_prefix%&#FFEE00&l%name%'
    lore:
      - '&7by &f%owner%'
      - '&#54ADF4Rating: %stars% &7(%votes%)'
    left_click_commands:
      - '[warp] %name%'
    right_click_commands:
      - '[menu] warp_info %name%'
    shift_left_click_commands:
      - '[favorite] %name%'
      - '[refresh]'
  empty:
    material: STRUCTURE_VOID
    display_name: '&#FFA42D&lNo warps'
  previous:
    material: ARROW
    slot: 48
  next:
    material: ARROW
    slot: 50
```

| Key | What it does |
| --- | --- |
| `source` | Where the entries come from |
| `slots` | Slots they fill, in order. Without it the three middle rows are used |
| `item` | Template for one entry |
| `empty` | Shown in the middle when there is nothing |
| `previous` / `next` | Page arrows, only drawn when there is a page to go to |

A list menu can still have normal `items` around it, and they read `%page%`, `%pages%` and
`%total%`.

### Sources

| Source | Lists |
| --- | --- |
| `warps` | Everything visible, with the player's sort, filter and search applied |
| `all_warps` | Everything, newest first. Staff also see hidden warps |
| `trending`, `top_rated`, `top_visits`, `top_favorites`, `top_level`, `newest` | One fixed ranking each |
| `my_warps` | The viewer's own |
| `favorites` | The ones they saved |
| `categories` | The categories |
| `reviews` | Reviews left on a warp |
| `trusted` / `banned` | That warp's lists |
| `promotion_tiers` | The tiers from the config |
| `icons` / `particles` | The pickers |
| `report_reasons` | The reasons from the config |
| `reports` | Pending reports |
| `milestones` / `stamps` | Passport contents |
| `sort_modes` | The sort options |

### Entry placeholders

Each source fills its own values in the entry.

| Source | Placeholders |
| --- | --- |
| Warp lists | Every [warp placeholder](#warp-placeholders) |
| `categories` | `%id%` `%name%` `%material%` `%description%` `%count%` `%visits%` `%locked%` |
| `reviews` | `%player%` `%stars%` `%value%` `%comment%` `%date%` |
| `trusted` / `banned` | `%player%` `%uuid%` `%date%` |
| `promotion_tiers` | `%id%` `%name%` `%material%` `%duration%` `%price%` `%priority%` `%balance%` |
| `icons` | `%id%` `%name%` `%material%` `%selected%` |
| `particles` | `%id%` `%name%` `%selected%` |
| `report_reasons` | `%reason%` |
| `reports` | `%id%` `%name%` `%owner%` `%reporter%` `%reason%` `%date%` `%total%` |
| `milestones` | `%amount%` `%pearls%` `%extra%` `%missing%` `%state%` `%material%` |
| `sort_modes` | `%id%` `%name%` `%selected%` `%material%` |

## Warp placeholders

Inside a warp list every entry has these without a prefix:

```
%name% %id% %owner% %description% %category% %category_id%
%stars% %rating% %votes% %your_rating% %favorite%
%visits% %visits_short% %recent_visits% %unique_visits% %favorites% %trend%
%level% %level_bar% %experience% %experience_next%
%tags% %tag_count% %icon% %particle%
%world% %x% %y% %z% %access% %access_list% %state% %state_list% %fee%
%created% %created_ago% %promotion% %promotion_prefix%
%trusted_count% %banned_count% %reports% %pearls_today% %featured% %hidden%
```

A menu opened for one warp, like `warp_edit` or `warp_info`, reaches the same values with a `%warp_`
prefix, for example `%warp_name%`. Any `%aquawarps_*%` from [Placeholders](./placeholders) works
everywhere.

<Callout type="warning">
  A command that still holds an unresolved `%warp_*%` is skipped instead of running broken, so a menu
  opened without a warp never acts on the wrong one.
</Callout>

## Actions

| Action | What it does |
| --- | --- |
| `[menu] <name> [warp]` | Opens another menu, for that warp if given |
| `[close]` | Closes the GUI |
| `[refresh]` | Redraws the menu without closing it |
| `[player] <command>` | Runs a command as the player |
| `[console] <command>` | Runs it as console |
| `[message] <text>` | Sends a message |
| `[sound] <SOUND>` | Plays a sound |

AquaWarps actions take the warp of the menu when no name is given.

| Action | What it does |
| --- | --- |
| `[warp] [name]` | Travels there |
| `[random]` | Travels to a warp never visited |
| `[favorite] [name]` | Saves or unsaves |
| `[rate] [name] <1-5>` | Leaves stars |
| `[unrate] [name]` | Removes the rating |
| `[reviews] [name]` | Opens the reviews |
| `[promote] [name] <tier>` | Buys a promotion |
| `[icon] [name] <material>` / `[hand-icon]` | Sets the icon, or uses the item in hand |
| `[particle] <particle>` | Sets the arrival effect |
| `[category] [name] <category>` | Files the warp. With no warp behind the menu it filters `browse` instead |
| `[access]` | Cycles public, password, private |
| `[toggle]` | Opens or closes the warp |
| `[clear-password]` / `[clear-description]` / `[remove-tag]` | Clears one thing |
| `[relocate]` | Moves it here |
| `[delete]` | Deletes it |
| `[untrust] [name] <player>` / `[unban] [name] <player>` | Removes a player from a visitor list |
| `[report] <reason>` | Reports it |
| `[sort] <mode>\|next\|previous` | Changes the order |
| `[filter] <category>\|clear` | Changes the filter |
| `[clear-search]` | Drops the search |
| `[buy-slot]` | Buys a warp slot |
| `[feature]` / `[hide]` | Staff flags |
| `[resolve] <id>` / `[resolve-delete] <id>` | Closes a report, optionally deleting the warp |
| `[input] <type> [menu]` | Asks in chat, then reopens that menu |

## Chat input

`[input]` asks the player to type the answer in chat, which is how warps get created, renamed and
described without a command.

| Type | Asks for |
| --- | --- |
| `create` | A name, then opens `warp_edit` for the new warp |
| `search` | Search text, then reopens `browse` unless another menu is given |
| `rename` | A new name |
| `description` | A description line |
| `tag` | A tag |
| `password` | A password, and switches the warp to `PASSWORD` |
| `fee` | An entry fee |
| `comment` | A written review next to the stars |
| `trust` / `ban` | A player for that list |
| `purge` | Days of inactivity, staff only |

```yaml filename="menus/warp_edit.yml"
    left_click_commands:
      - '[input] rename warp_edit'
```

Timeout, cancel words, bossbar and sounds are set in [Configuration](./configuration#chat-input).
